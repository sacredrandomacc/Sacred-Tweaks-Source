# Quality and security review

Reviewed `fd776b2...d9471db` against `docs/ARCHITECTURE.md` and `docs/CONTRACT.md`. Existing 76 passing tests were not rerun. Findings are based on source inspection; Windows execution and deployment were not verified.

1. **P1 — Alternate auth URLs expose bearer tokens to the renderer.** `desktop/bridge.py:128–156` only recognizes exact login/register paths, whereas `server/service.py:279–280` removes trailing slashes and parses queries. Calling `request("POST", "/v1/auth/login/", credentials_with_device_id)` therefore creates a real session through the generic branch and returns its raw `token` to JavaScript. `/v1/auth/login?x=1` and equivalent register paths behave similarly. This also bypasses `_accept`'s Manager owner check, device-ID insertion, generation checks, and native session installation. Canonicalize paths before classification (or reject noncanonical auth URLs), enforce the method, and prevent any generic response from exposing a token. Add boundary coverage for both URL forms and both auth endpoints.

2. **P2 — An old request can sign out a newer session.** `desktop/bridge.py:151–160` captures the token but not its generation; a delayed unauthorized/disconnected response unconditionally calls `_clear`. If the user signs out and successfully signs in while an earlier request is pending, that earlier response clears the new login and stops its tools. `_renew_once` has the same smaller race at `180–183`: its generation check and clear are separate critical sections. Carry the request generation and token into an atomic conditional clear, including heartbeat/expiry paths. Verify with a blocked old request that fails after a new session is installed.

3. **P2 — Settings writes can cross into a different authorization snapshot.** `desktop/native.py:578–586` validates feature permissions and enforced values before `SettingsManager.apply` performs file reads, backup writes, and process checks. Its last authorization check (`desktop/settings.py:227`) calls the generic `_require`, which checks only the current lease. A logout followed by login with a different license while that I/O is pending can therefore apply an old advanced/potato plan under a new account lacking that feature or requiring different values. The action lock does not serialize `set_authorization`. Bind pending mutations to an authorization generation and reject generation changes; recheck the plan's complete feature/policy requirements immediately before writing. Include an interleaving test that changes authorization during backup creation.

## Resolution by implementer

All three original findings were addressed. The bridge rejects alternate routes (including empty queries and control characters), injects its own device ID, and handles authentication only through the token-stripping owner-aware branch. Clearing sessions now compares a captured generation atomically, including heartbeat failures and expiry.

Settings and Filter Keys writes capture an authorization generation and recheck full permission/enforcement requirements immediately before commit. A separate authorization lock serializes snapshot changes with the final write; the input/watchdog lock is not held during disk/platform I/O. Emergency stop and status bypass the disk-action queue. Stop releases input before waiting for authorization updates. A write already started while authorized may finish; revocation stops input and prevents subsequent writes.

Follow-up review identified an empty-query variant and an initial watchdog-blocking lock implementation; both were corrected. Added regression coverage exercises alternate authentication routes, late failures after new login, an authorization change during backup creation, and emergency release during a stalled settings write. The full suite passes 83 tests. Final closure was checked by the implementer; there was no completed independent final re-review or Windows execution.
